# バンケットサービス - 動的コンテンツ管理システム

岐阜キャッスルイン バンケットサービスの料理ページと料金シミュレーターを、Google Sheetsから編集可能にするシステムです。

## システム構成

```
Google Sheets（データ編集）
    ↓
Google Apps Script（JSON API）
    ↓ fetch
GitHub Pages（cuisine.html / simulator.html）
    ↓ iframe
WIX サイト（メインHP）
```

## セットアップ手順

### 1. Google Spreadsheet を作成

「バンケットサービス データ管理」という名前でスプレッドシートを作成し、以下の6シートを作ります。

#### シート「料理プラン」

| id | label | price | note | description | image | badgeText | badgeColor | sortOrder | active | venueIncluded |
|----|-------|-------|------|-------------|-------|-----------|------------|-----------|--------|---------------|
| kaiseki | 会席料理 | 5200 | コース料理・個別提供 | お一人おひとりに... | (画像URL) | 個別提供 | primary | 1 | TRUE | TRUE |

- `id`: 英数字のID（重複不可）
- `price`: 税込金額（数値のみ、カンマなし）。**コースを1件でも登録したカテゴリでは無視され、コースの最安値が自動で使われる**
- `badgeColor`: `primary`（紺）/ `accent-gold`（金）/ `gray-800`（グレー）
- `active`: `FALSE` にすると非表示
- `venueIncluded`: `TRUE` の場合、このプラン選択時は会場費が無料になる

#### シート「コース」（initCourseSheet() で自動作成可）

各料理カテゴリの中に複数のコース（例: 5,200円コース / 7,700円コース）を登録するシート。

| id | categoryId | label | price | images | description | sortOrder | active |
|----|-----------|-------|-------|--------|-------------|-----------|--------|
| kaiseki_5200 | kaiseki | 5,200円コース | 5200 | ["画像URL1","画像URL2"] | 前菜、椀物、造里… | 1 | TRUE |

- `categoryId`: 親カテゴリ（料理プランの `id`）。管理画面ではプルダウンで選ぶだけ
- `images`: 画像URLのJSON配列（**複数枚OK**）。管理画面では「1行に1URL」を貼るだけで自動変換される
- コースを登録すると: ①料理ページにコースカードが並び、クリックで写真ギャラリー付きの詳細が開く ②シミュレーターでカテゴリ選択後にコースを選べるようになり、選んだコースの価格で計算される ③カテゴリの「〜円から」表示がコースの最安値に自動更新される
- **コースが0件のカテゴリは従来通り**（料理プランの price・image がそのまま使われる）。カテゴリごとに少しずつ移行してOK

### 2. GAS API をデプロイ

1. スプレッドシートの「拡張機能」→「Apps Script」を開く
2. `gas/Code.gs` の内容をコピー＆ペースト
3. 「デプロイ」→「新しいデプロイ」→「ウェブアプリ」
   - 実行するユーザー: **自分**
   - アクセスできるユーザー: **全員**
4. デプロイ後のURLをコピー

### 3. API URL を設定

`js/banquet-data.js` の先頭にある `BANQUET_API_URL` にデプロイURLを設定:

```javascript
var BANQUET_API_URL = 'https://script.google.com/macros/s/あなたのデプロイID/exec';
```

### 4. GitHub Pages を有効化

1. GitHubにリポジトリを作成（Public）
2. ファイルをpush
3. Settings → Pages → Source: `Deploy from a branch` → Branch: `main` / `/ (root)`
4. 数分後にURLが有効に

### 5. GitHub Secrets を設定

リポジトリの Settings → Secrets and variables → Actions:

| Secret名 | 値 |
|----------|-----|
| `BANQUET_API_URL` | GASデプロイURL（`?type=` パラメータなし） |

### 6. WIX に iframe を埋め込み

- 料理ページ: `https://あなたのユーザー名.github.io/banquet-service/cuisine.html`
- シミュレーター: `https://あなたのユーザー名.github.io/banquet-service/simulator.html`

WIXエディタ → 「要素を追加」→「埋め込みコード」→「HTMLを埋め込む」→ 「ウェブアドレス」に上記URLを入力。

## 運用ガイド

### 料理の料金を変更する

1. Google Sheetsの「料理プラン」シートを開く
2. 該当行の `price` 列の数値を変更
3. ページをリロードすると即座に反映

### 料理プランを追加する

1. 「料理プラン」シートの最終行に新しい行を追加
2. 各列を入力（idは他と重複しない英数字）
3. `sortOrder` で表示順を指定
4. `active` を `TRUE` に設定

### 料理プランを非表示にする

1. 「料理プラン」シートの該当行の `active` 列を `FALSE` に変更

### ページの見出し・キャッチコピーを変更する

1. 管理画面の「ページ文面」タブを開く
2. 上の「ページで絞り込み」で編集したいページを選ぶ
3. 該当行の「編集」→ `value` 欄を書き換えて保存（**入力は普通の文章だけ。HTMLタグは書かない**／改行はそのまま反映される）
4. 右上の「サイトに今すぐ反映」→ 1〜2分でサイトに反映

- 「全ページ共通」の項目（フッターの受付時間など）は1回直せば全ページに反映される
- 住所・電話番号は「施設情報」タブが正本（文面タブには出てこない）
- **欄を空にして保存しても現在の文面は消えない**（安全のため元の文面が残り、ビルドログに警告が出る）
- 項目の追加・削除・キーの変更はできない（キーはHTML側の目印と1対1で対応しているため）

### 料理カテゴリにコースを追加する（推奨: 管理画面から）

1. 管理画面（`?page=admin`）の「料理コース」タブ →「＋追加」
2. `categoryId` をプルダウンで選択（会席・シッティング等）
3. コース名・価格を入力
4. 写真は「1行に1URL」で複数貼り付け（Googleドライブの共有リンクでOK。下にサムネイルが出る）
5. 保存 → 料理ページ・シミュレーターにリロードで即反映

コースの価格を変えたり非表示（`active` を FALSE）にすると、カテゴリの「〜円から」表示も自動で追従する。

### 備品を追加・変更する

1. 「備品」シートを編集

### シミュレーターの飲物を追加する

1. 「飲物」シートに新しい行を追加

## 管理画面（編集UI）

スプレッドシートを直接触らず、フォームで編集・追加・削除できる管理画面を GAS 内に用意している。**公開APIと同じ単一デプロイ**（実行=自分／アクセス=全員）で動き、`?page=admin` で管理画面を返す。認証は**共有パスワード方式**。

- **URL**: `https://script.google.com/macros/s/＜デプロイID＞/exec?page=admin`（APIと同じ /exec に `?page=admin` を付けるだけ）
- **認証**: 開くとパスワード入力。スクリプトプロパティ `ADMIN_PASSWORD` と一致すれば操作可（従業員には別途パスワードを共有）。データ取得・書き込みは全てサーバ側でパスワード検証するため、パスワードなしでは何も見えない・触れない。
- **できること**: 料理プラン / 料理コース / フリードリンク / 会場 / 備品 / 飲物 / 施設情報 / ページ文面 / SEO の一覧・追加・編集・削除・並び替え
  - ページ文面は**既存項目の編集のみ**（追加・削除・キー変更は不可）。ページで絞り込んで編集する
  - 会場の `layouts`（レイアウト別人数）は「名前＝人数」の入力欄、`foodPlans` は料理プランのチェックボックスで編集（JSON手打ち不要）
  - 料理コースの `images`（複数枚写真）は「1行に1URL」のテキスト欄＋サムネイルプレビューで編集（JSON手打ち不要）
- **反映タイミング**:
  - 料理・会場・料金など（データページ）＝ページを**リロードすれば即反映**
  - SEO・フォールバックデータ＝毎朝3時の自動同期、または管理画面の**「サイトに今すぐ反映」ボタン**（1〜2分）

### セットアップ（初回のみ）
1. `gas/Code.gs`・`Admin.html`・`AdminJs.html`・`AdminCss.html` を Apps Script プロジェクトに配置
2. 「プロジェクトの設定 → スクリプト プロパティ」に `ADMIN_PASSWORD` を追加（強めのパスワードを設定）
3. GASエディタで `updateSeoSheet()` を1回実行して `SEO` シートを作成
4. GASエディタで `initCourseSheet()` を1回実行して `コース` シートを作成（既にあれば何もしない）
5. `gas/SeedTexts.gs.txt` の中身をGASに貼り、`seedTexts_()` を1回実行して `文面` シートを作成・投入
6. 「デプロイを管理 → 編集（鉛筆）→ バージョン: 新バージョン」で更新（**URLは固定のまま**／デプロイは1つでOK）
7. 「今すぐ反映」を使う場合: GitHub の fine-grained PAT（`contents:write` 相当）を発行し、スクリプトプロパティに `GITHUB_PAT` として登録

> パスワードを変えたいときはスクリプトプロパティ `ADMIN_PASSWORD` を書き換えるだけ（再デプロイ不要）。

## ページ文面（自動焼き込み）

見出し・キャッチコピー・リード文などの文面は、HTMLに埋めた目印 `<!--T:キー-->…<!--/T-->` の中身を、
`文面`シートの値で **`scripts/build-texts.js`** が静的に書き換える（SEO と同じ GitHub Actions 経路）。

- 目印の中は**プレーンテキスト**として扱われ、`&<>` はエスケープ、改行は `<br>` に変換される。
  管理画面でタグを入力しても文字として表示されるだけで、レイアウトは壊れない
- 同じキーを複数ページに埋めてあるので（ヘッダー/フッター）、**1回の編集で全ページに反映**される
- `facility.*` のキーは`文面`シートではなく **`設定`シート（施設情報）が正本**。住所・電話の二重管理を避けるため
- 電話番号は表示だけでなく **`tel:` リンクの飛び先も追従**する（表示と発信先が食い違わない）
- 安全機構:
  - シートが空／キーが無い／値が空 → **既存の文面を保持して警告**（サイトの文字が消えない）。
    警告は GitHub Actions の Summary に一覧表示されるので、ログを掘らなくても気づける
  - HTML側の目印が壊れている → 1ファイルも書き込まずにビルドを失敗させる
  - CI で API の応答が壊れている → **サンプルデータで代用せずビルドを失敗させる**
    （古い文面を「正しいデータ」として公開してしまうのを防ぐ）
- 現状の対象は第1期分（共通ヘッダー/フッター＋各ページのヒーロー・CTA・リード文の65キー）。
  JS内で描画している文面（料理ページの特典ブロック等）と `alt`・`tel:` などの属性値は対象外

### 文面キーを追加するとき（開発者向け）

1. 対象のHTMLで、差し替えたいテキストを `<!--T:page.section.element-->` 〜 `<!--/T-->` で囲む
   （装飾タグの**内側のテキストだけ**を囲むこと。タグをまたぐ場合はキーを分ける）
2. `node scripts/extract-texts.js` を実行（4種の検証＋ `spreadsheet-data/07_文面.seed.json` と
   `gas/SeedTexts.gs.txt` を再生成）
   - 検証: 目印の構造／`<br>`以外のタグの混入／`&copy;` など往復できない文字コード表記の混入／
     同じキーがページ間で違う値になっていないか
3. `gas/SeedTexts.gs.txt` の中身をGASに貼り、`seedTexts_()` を1回実行してシートへ投入
   （**upsert方式**なので再実行しても既存の `value`＝スタッフが編集した文面は保持される。
   新しいキーだけ追加され、HTMLから消えたキーはログに報告されるだけで自動削除しない）
4. 「サイトに今すぐ反映」を押し、Actionsのログが **置換n件・警告0件** になることを確認

## SEO（自動焼き込み）

各ページの `<head>` の meta / OGP / canonical / 構造化データ（JSON-LD）は、`SEO` シート＋`設定` シートを元に **`scripts/build-seo.js`** が静的に生成する（GitHub Actions が実行）。`sitemap.xml` / `robots.txt` も自動生成。

- HTML内の `<!-- SEO:AUTO:START -->` 〜 `<!-- SEO:AUTO:END -->` は**自動生成領域**。手で編集しない（次回同期で上書きされる）。
- title / description / OGP画像は管理画面の「SEO」タブから編集。
- GA4を使う場合: GitHub Secrets に `GA4_ID`（`G-XXXXXXXXXX`）を登録。
- Google Search Console は **DNSのTXTレコード方式**を推奨（ファイル不要）。
- `favicon.ico` / `apple-touch-icon.png` はロゴから作成してリポジトリ直下に置く（未配置でも表示は問題なし）。

## 画像の最適化（WebP自動変換）

サイトの静的画像は **WebP** で配信して軽量化している（PNG比で概ね 95〜99% 削減）。

- **既存画像**は `scripts/optimize-images.py`（Pillow）で長辺1600px・WebPに変換済み。`images/` には `.webp` と、既に軽い `.avif` のみを置く。
- **今後の追加は GitHub Actions が自動変換**（`.github/workflows/optimize-images.yml`）：
  - `images/` に PNG/JPG を追加して push（GitHubのWeb UIでのアップロードでもOK）すると、CIが自動で WebP 化・リサイズ・**元画像削除**・HTMLの参照張り替え・コミットまで行う。
  - **どのPC・誰でも**、ローカルにツール不要で軽量化される。
- **管理画面から入れる画像**（料理・会場の image 欄＝Googleドライブリンク）は、Google側が自動でWebP配信するため対応不要。
- 手元で一括変換したいときは:
  ```bash
  python scripts/optimize-images.py --delete-source --fix-html
  ```
  （`--max` で長辺px、`--quality` で品質を調整可能）

## GAS コード更新時の注意

コードを修正した場合は、必ず「デプロイ」→「**新しいデプロイ**」で新バージョンを作成してください。
「デプロイを管理」から既存デプロイを編集しても反映されません。

新しいデプロイURLが発行されるので、`js/banquet-data.js` と GitHub Secrets の `BANQUET_API_URL` を更新してください。

## トラブルシューティング

### ページに変更が反映されない
- ブラウザのキャッシュをクリア（Ctrl + Shift + R）
- GASのデプロイURLが正しいか確認
- スプレッドシートの `price` 列に数値以外（カンマ、円マーク等）が入っていないか確認

### シミュレーターの計算が合わない
- スプレッドシートの `price` / `base` / `extra` 列が税込金額の数値であることを確認

### APIがエラーを返す
- GASのデプロイが「全員」に公開されているか確認
- スプレッドシートのシート名が正確か確認（「料理プラン」「コース」「フリードリンク」「会場」「備品」「飲物」「設定」）

### 文面を変更したのにサイトに反映されない
- 「サイトに今すぐ反映」を押したか（文面はリロードでは反映されない。1〜2分かかる）
- GitHub Actions のログで警告が出ていないか（`シートにキーがありません` / `値が空です` の場合は元の文面が保持される）
- GAS側に最新の `Code.gs` が反映され、新バージョンでデプロイ更新されているか（`?type=texts` が動くか）

### コースが表示されない
- 「コース」シートが存在するか確認（無ければGASエディタで `initCourseSheet()` を実行）
- 該当行の `categoryId` が料理プランの `id` と一致しているか、`active` が `TRUE` か確認
- GAS側に最新の `Code.gs` が反映され、新バージョンでデプロイ更新されているか確認
